# Buildings

Draw a plan, and get a building. Not a box with a texture on it — real storeys, real bays,
windows that land on whole numbers, a roof that fits an L-shaped plan without being told
about the L, and trim that mitres round the corners.

Buildings are a **workspace of their own**, reached from **Buildings** in the top navigation.

> Everything on this page runs in the browser. There is no service to start and no model to
> download — a building is a few hundred lines of arithmetic, so the preview keeps up while
> you drag a slider.

## The graph is the building

This is the one idea worth understanding first, because everything else follows from it.

A building is a small **node graph**: a plan, then a stack of operations that turn it into a
building. The graph *is* the asset — about 20 KB of JSON. The mesh is an output it can produce
again at any time.

That is what makes the page work the way it does:

- **Nothing is destructive.** Every setting can go back where it was.
- **Re-rolling costs nothing.** Change the seed and every seeded choice is re-rolled — which
  window model goes in which hole, which panels get a brace, which openings get a balcony.
- **Saving saves the graph**, so a building made months ago can be reopened and nudged.

## The chain

Nodes run in order, and **the order matters**. The list on the left is the pipeline, top to
bottom, and the arrows beside each node move it.

**Footprint** — the plan, drawn on the **Plan** tab. Holes become courtyards and light wells,
and they survive everything above: a courtyard block is one footprint with one hole, not two
buildings.

**Mass** — stacks the plan into storeys. The **Profile** is the important control and is what
separates one style from another:

| Profile | What it does | Where you have seen it |
|---|---|---|
| Straight | walls rise vertically | most things |
| Batter | leans inward with height | Egyptian pylons, Asian taper |
| Setback | steps inward every few storeys | Mayan platforms, deco towers |
| Jetty | oversails outward | medieval overhangs, cantilevers |
| Curve | you draw the inset against height | shells, bulges, waists |

**Facade** — splits every wall into bays and places the openings. **Chain several**, each set
to different storeys, to give a building a shopfront, a grander first floor and a plainer
attic. A later Facade replaces an earlier one only on the storeys it claims.

**Frame** — half-timbering: studs between the rails and braces across the panels. Set its
panel width to match the Facade's bay width and no stud lands through a window.

**Roof** — caps the building. A second Roof **continues** the first rather than replacing it,
which is how a Mayan temple (stepped, then hipped) and a pagoda (tiered over tiered) come out
of the same two nodes. The roof below needs a height cap so it ends on a deck.

**Roof Detail** — chimneys, finials, vents and ridge crests. It reads the roof under it, so it
must come *after* the Roof. Put it before and the editor says so and offers to move it.

**Trim** — a moulding along an edge: a plinth, a string course, a cornice, an eave, a parapet,
or a bargeboard up a gable. Trim follows *edges*, which is why it mitres round a corner
instead of leaving a notch. One node is one run; add three.

**Deform** — bends the finished building. Twist, lean, bend or sag, all seeded so a crooked
building is the *same* crooked building every time. **Hand-set** is separate: it nudges each
window, post and chimney off true by a little, each its own way, and leaves the walls dead
straight. Turn the warp off and use Hand-set alone for a building that was built by hand
rather than one that settled.

### Wings, towers and porches

**Add a wing** builds a second Footprint, Mass and Roof and merges them into the first. Each
part keeps its own roof, which is the only way to get a tower beside a hall, or a porch in
front of one. Add a wing again for a third. The **Editing** pill above the plan switches which
plan you are drawing.

## Bays snap to whole numbers

Bay width is a **nominal**. Every wall is divided into a whole number of equal bays nearest
that width, so nothing lands half-cut at a corner — and the openings keep their own size while
the wall around them takes up the slack. That is why one setting fits walls of any length, and
why widening a wall adds a window rather than stretching the ones already there.

## Styles

The **Style** dropdown applies a whole look: eleven ship, grouped by category. A style is a
**recipe**, not a paint job — it rebuilds the nodes between the Footprint and the Output, so
it changes the massing too. Your plan is kept, and undo restores the previous graph.

Pick one as a starting point, then change whatever you like: the result is an ordinary graph
with no memory of where it came from.

## Colours and textures

**Colours** sets what each kind of surface shows when it has no texture on it: walls, trim and
timber, roof, windows, doors, posts. **Textures** binds an image to the same slots, and a
texture *replaces* the colour.

A slot holds a **list**, not one asset. Give the wall three bricks and the windows three
models, and a street of these stops looking like one building copied — the choice is rolled
from the seed, once per building for a texture and **once per opening** for a model.

- A **wall**, **roof** or **trim** texture tiles by metres, so brickwork is the same size on a
  cottage and on a tower.
- A **window**, **door** or **post** texture fills its opening instead, because it is one
  object rather than a material. Transparency is honoured, so a window cut out around its arch
  shows the wall through the corners.

A **chimney** or a **balcony** has no colour of its own and borrows the wall's or the trim's,
so a texture on those never paints over a model you imported — an imported chimney keeps its
brick.

**Openings** binds real models instead of the placeholder boxes. A model is fitted to the hole
the grammar worked out, so one window fits any wall; if it was exported lying down, turn it
with the X/Y/Z fields beside it.

A **Facade** can override the wall, the windows, the posts and their models on the storeys it
covers — and again on **one side** of them, which is how a street frontage gets shopfronts
while the back stays plain. Openings, balconies and posts can each be limited to chosen sides.

## Export

**Export** saves the building into the asset library as a mesh, with a five-level **LOD
chain**. The levels are *regenerated from the graph* at lower detail — wider bays, no trim,
plainer openings, then massing only — rather than decimated, which is what keeps a distant
building's silhouette intact. From there it goes through the ordinary mesh pipeline:
collision hulls, FBX, engine presets.

**Nothing is ticked to begin with**, including the full-detail level. Whichever levels you do
tick, the finest becomes the library entry and the rest are saved as versions of it. A merge
or an impostor is a perfectly good thing to want on its own, and forcing the full model into
every export made the cheap outputs cost the expensive one — so ticking nothing but
**Impostor** saves two images and no mesh at all.

The models bound to the openings go **into** the export, and each level gives them less detail
than the one above it.

## Detail costs what it is used for

A model in a slot is drawn once per opening, so binding a 12,000-triangle window to a tower
with two thousand of them is twenty-four million triangles. Models are therefore **simplified
to fit how often they appear**: a cottage with forty windows keeps them whole, and the same
model on a tower is reduced until the whole facade fits one budget. Nothing needs setting —
but it is why a detailed model looks slightly softer on a very large building than on a small
one, and why the fix for a slow building is fewer *kinds* of model rather than simpler ones.

The budget is shared over **every** instance in the building, so all models get the same
allowance. Sizing each kind against its own count would give a model placed once — a door, a
chimney — the whole budget and leave it at full detail forever, which is exactly what used to
happen: a cottage's door and chimney were two thirds of the coarsest modelled level.

Each coarser LOD then does three things rather than one: wider bays, **fewer posts**, and a
smaller budget. The posts matter because widening a bay does not remove any — a post stands at
a bay *boundary*, and a plan whose edges are already shorter than one bay keeps two per edge
however wide the bays get. A curved plan drawn as a polygon is exactly that shape, which is
why a tower ringed with fins had three levels that all cost the same. Where a model still
cannot meet its budget — every simplifier stops somewhere — the level draws the placeholder
box instead, which is the same judgement the coarsest level makes when it drops the openings
altogether.

**Massing only is a cliff, and that is correct.** It is the last level and it removes every
opening, so on a building whose cost is its windows it is a hundredth of the level above.
That level is the distant silhouette; the levels above it are the ones that have to grade
smoothly into each other.

## One mesh, one texture

**Merge into one mesh** bakes every surface into a shared texture and exports the building as
a single mesh. Pick the texture size; **Materials** caps how many atlases the opaque surfaces
may spread over.

Nothing is re-unwrapped. A building already has a perfectly good parameterisation — its walls
are measured in metres and its windows fill their own square — so the merge repacks what is
there rather than inventing new seams. Atlas space is handed out by real surface area, which
is why a 150 m tower in a 2048 texture comes out at about 13 pixels per metre: that is what
one texture for a whole building means, and the answer is a bigger texture rather than a
cleverer packer.

**More materials is usually the wrong knob.** Detail grows with the square root of the texture
area, so a second material buys about 1.4x the density rather than twice it — and each extra
atlas is emptier than the last, so past three it stops buying anything. One step up in texture
size is four times the area in a *single* draw call, which beats four materials at the smaller
size. Measured on the twisted tower at 2048: one material 1.7% detail at 89.8% full, two 2.8%
at 85%, three 3.4% at 75.1%, four 3.3% at 73.2%.

**Materials means materials.** Ask for one and you get one. If anything in the building punches
holes — a window model with a cut-out, a texture with alpha — then the merged material is
alpha-tested, and that costs nothing: a masked material writes depth and sorts exactly like an
opaque one. Only *blending* needs ordering, and a cut-out is not blended.

**The texture size is the quality setting, not a limit.** Everything fits whatever you pick;
what changes is the density. **How much detail?** measures it — `2% of the source detail, 89.8%
full` — so a 150 m tower in a 2048 atlas is a choice you can see rather than an error. Detail
is share of the source textures' own resolution, and a building with a lot of surface spends it
quickly.

It sits behind a button rather than appearing on its own because the only way to know the real
figure is to run the packing, which takes seconds on a large building. Estimating it from the
areas alone is instant but overstates the answer by anywhere from two to nine times, because
most of a crowded atlas is the gutter around each island rather than the island.

## Impostor

**Impostor** replaces the building with a billboard carrying pre-rendered views, for the
range where even the massing is a few pixels. The views are a hemi-octahedral grid — the lower
half is left out because nobody looks at a building from below — and a shader picks the ones
nearest the camera and blends them, so the billboard turns as you walk past it.

It is baked on the mesh service, so unlike everything else on this page it needs Python
running.

**Views per axis** and **View size** set the grid. Eight per axis is 64 views in a 1024 atlas —
the default, and the point at which the turn stops stepping. Four per axis is 16 views and
bakes in seconds, which is what you want while trying things out; sixteen is 256 views and
wants a large tile to be worth the wait, so mind the atlas it adds up to.

**What gets saved is two images.** The albedo atlas goes into the library as an **image**, and
the normal atlas as an **edit of it** — same bake, same views, same layout, so it belongs
underneath rather than beside. Its `impostor` metadata describes the layout: grid, mapping,
bounds and quad size.

No mesh is saved. The billboard is four vertices an engine builds itself from that metadata,
and the version that used to be saved also carried a second copy of the albedo embedded in it.

The Export dialog names whatever dominates a level (`98% pillars`) and says so when a level
is barely cheaper than the one above it.

## Also reachable from an agent

The MCP server exposes the whole loop — `describe_building_catalog`, `create_building_graph`,
`compile_building`, `apply_building_style`, `set_building_reference`, `save_building` — so a
building can be authored, checked and saved without opening the page. Buildings saved that way
show a placeholder card until someone opens and saves them in the editor, because rendering a
thumbnail needs a GPU.
